# Khmer24: ручной сбор на Mac → обработка и каталог на VPS

Статус на 2026-11-10: **обработчик развёрнут на VPS; первый тест на пяти объявлениях и последующий полный ручной сбор за 14 дней выполнены**. Во втором запуске собрано 69 исходных объявлений (27 домов, 39 квартир, 3 комнаты), из них 64 новых для источника; в общей базе стало на 56 canonical карточек больше и на 43 видимых объявления больше. Все батчи подтверждены, локальная очередь пуста. Можно запускать сбор вручную из терминала Mac, без расписаний и Telegram-кнопок.

## Как устроено

Mac запускает существующий Khmer24 Camoufox/Playwright scraper, считывает исходные объявления и сохраняет их в `data/k24_outbox/` в маленьких JSON-батчах (по 5). Далее передаёт по HTTPS с отдельным секретом в `POST /api/v1/internal/khmer24/ingest`. VPS применяет существующую обработку Khmer24: AI-обогащение, классификацию, дедупликацию и canonical SQLite; публикация зависит от текущих правил модерации и свежести. Подтверждённые VPS батчи удаляются с Mac, неподтверждённые остаются для повторной отправки.

На VPS браузер Khmer24 оставляем выключенным: его исходящий OVH IP получает Cloudflare 1005 (ASN blocked). Сбор запускается на Mac через его обычное подключение. **Локальный Docker не запускать**: Compose проекта сейчас предназначен для VPS и может поднять лишние процессы.

## 1. VPS — уже настроен, повторять не нужно

Новый код избирательно установлен на VPS `/home/ubuntu/homeasy`, **только API** пересобран. Отдельный секрет `K24_INGEST_TOKEN` уже задан на VPS и Mac, `K24_INGEST_URL` — на Mac. Исходные файлы VPS сохранены в `/home/ubuntu/.homeasy-deploy-backups/khmer24-20261110/`, прежний Docker-образ — `homeasy-api:before-khmer24-20261110`. Не повторяйте развёртывание, не генерируйте новый токен и не делайте `git pull` ради обычного сбора.

При желании проверить, доступен ли API, без отправки объявлений:

   ```bash
   curl -sS -o /dev/null -w '%{http_code}\n' -X POST \
     'https://api.rustycat.cc/api/v1/internal/khmer24/ingest' \
     -H 'Content-Type: application/json' -d '{}'
   ```

   Для уже развёрнутого API проверено **401** без токена и **400** для авторизованного, но некорректного тела. `/health` вернул **200**. Эти ответы и реальная доставка пяти записей подтверждены 2026-11-10.

## 2. Один раз: подготовить Mac

В Terminal VS Code из корня проекта (`/Users/lacr0s/!Projects/homeasy`):

```bash
cd '/Users/lacr0s/!Projects/homeasy'
```

В локальном `.env` уже настроены (значение токена не копировать в переписки):

```dotenv
K24_INGEST_URL=https://api.rustycat.cc/api/v1/internal/khmer24/ingest
K24_INGEST_TOKEN=ВСТАВИТЬ_СВОЙ_64_СИМВОЛЬНЫЙ_СЕКРЕТ
```

Обратите внимание: загрузчик проверяет **все** заданные URL. Если в Mac `.env` остался неверный `FB_INGEST_URL`, исправить его до корректного `https://...` или убрать эту строку; иначе запуск Khmer24 тоже остановится при чтении настроек. Facebook при этом запускать не нужно.

На этом Mac Node-зависимости и Python-окружение Camoufox уже установлены. Для нового компьютера: если Node-зависимости отсутствуют, выполнить `npm ci`; Python-окружение и **проверенную совместимую версию браузера** установить так:

```bash
python3 -m venv .venv-camoufox
.venv-camoufox/bin/pip install -r scripts/camoufox/requirements.txt
.venv-camoufox/bin/python -m camoufox fetch official/stable/152.0.4-beta.30
```

В этом локальном окружении вызов `.venv-camoufox/bin/camoufox` имеет старый абсолютный путь в shebang; при ручных операциях используйте `.venv-camoufox/bin/python -m camoufox`. В существующем Mac браузер `152.0.4-beta.30` уже установлен. Если Khmer24 требует повторной авторизации, вручную выполните `npm run k24:login` на **Mac** и пройдите вход в браузере. Сессионные файлы `data/k24_session.json` и `data/k24_device.json` не переносить на VPS и не публиковать.

## 3. Каждый ручной запуск

Первый пробный сбор **5 домов** по первой категории уже проведён и успешно доставлен. При необходимости повторить такой ограниченный запуск:

```bash
npm run scrape:khmer24:remote -- --target=0 --limit-listings=5
```

Для обычного ручного сбора по **трём категориям** (дома, квартиры, комнаты; лимит на каждую) выполните в Terminal VS Code:

```bash
npm run scrape:khmer24:remote -- --limit-listings=10
```

Для полного ручного сбора только за **последние 14 дней** по трём категориям (команда, применённая 2026-11-10):

```bash
npm run scrape:khmer24:remote -- --days=14
```

В большой загрузке 2026-11-10 медленные резервные модели Gemini привели к HTTP 524 через Cloudflare и таймауту 180 секунд у отправителя. При таком сбое исходные JSON-файлы остаются в очереди; после проверки состояния VPS их удалось доставить небольшими пакетами через локальный SSH-туннель. Повторная отправка пакета иногда совпадает с ещё работающей обработкой на VPS, поэтому сначала нужно проверить, завершился ли предыдущий запрос. Если обычный `k24:flush-outbox` снова упирается в таймаут, не удаляйте файлы вручную — потребуется проверить журналы API и повторить отправку малыми пакетами.

Если во время отправки пропала связь или API недоступен, уже записанные JSON-батчи останутся в `data/k24_outbox/`. После восстановления VPS можно повторить доставку, **не запуская браузер повторно**:

```bash
npm run k24:flush-outbox
```

Ненулевой код завершения или ошибка HTTP означает, что доставка могла остаться незавершённой. Не удалять очередь вручную и не считать число собранных объявлений числом опубликованных карточек. Повторная доставка уже принятых данных обрабатывается общим механизмом дедупликации; новая карточка может ждать модерации. Никаких кронов, Docker на Mac, Facebook/Camoufox групп или платных запусков Bright Data эти команды не включают.

Успешный локальный запуск показывает строки `VPS canonical ingest` с `new`, `updated`, `unchanged` и итоговым `Errors: 0`. Успешная отправка освобождает соответствующие `.json` из `data/k24_outbox/`. При первом реальном запуске (2026-11-10) получилось **5 новых исходных записей и 5 canonical**, из них **3 одобрены и публичны, 2 ждут модерации**. Публичный API показывал **190 → 193** карточки, `PRAGMA quick_check=ok`. Следующие запуски могут давать обновления/дубликаты и карточки на модерации, поэтому число собранных не равно числу опубликованных.
