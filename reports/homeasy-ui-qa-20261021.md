## Open investigations (insufficient evidence for a cause)

- At least one published card has a Khmer-language title; the owner also saw fresh cards apparently copied from source. Capture specific **public refs/source URLs** and compare canonical `title`/`description`, source `raw_text` and ingestion/classification status. A visible original-language title alone does not prove that no AI provider was called. Do not invoke paid LLMs, scrape live groups, or rewrite inventory during diagnosis.
- Some photo placeholders/failed images appeared during QA. Capture failing card ref, image URL and browser network status before choosing a fix; missing image source and blocked loading have different causes.

## Map provider update

The owner selected OpenFreeMap Liberty, integrated through MapLibre GL Leaflet. Map name labels prefer `name:en`, `name_en` and `name:latin`; name labels without those fields are suppressed, so English/Latin coverage depends on the underlying map data. The map engine remains lazy-loaded. The production build passes with a Vite large-chunk warning for the MapLibre map bundle; OpenFreeMap's public hosting has no SLA and may be discontinued.

## Passing checks from public browser audit

Feed initial load, Cheapest, Most Expensive, Apply/Cancel/Reset, restored filters after drawer reopen, and reload were observed working in the checked browser session. These observations are not a substitute for Telegram WebView QA.

Latest local verification after the map/filter changes: backend Jest **911/911 tests (85/85 suites)** using `npm test -- --runInBand --forceExit`; frontend Vitest **60/60**; root TypeScript and ESLint passed; frontend ESLint exited 0 with seven warnings; production frontend build passed with the large MapLibre chunk warning; `git diff --check` passed. Jest's existing open async-handle warning remains. These checks do not constitute a deployed-browser or Telegram WebView retest.
