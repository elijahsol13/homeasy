# Pending v13: проверка цены и восстановления исходных фактов

Дата проверки: 2026-11-12. Использована отдельная read-only копия production SQLite от 2026-11-11: `/private/tmp/homeasy_pending_v13_prod_20261111.sqlite`. В копии 153 карточки со статусом Pending. Текущее состояние VPS в этой проверке заново не запрашивалось.

Это локальное повторное вычисление правил и просмотр сохранённых первоисточников. Ни статусы карточек, ни production SQLite не менялись; новые сборы и платные AI-вызовы не запускались.

## Явная месячная цена

| ID | Цена в карточке | Что подтверждает оригинал |
| ---: | ---: | --- |
| 16565 | $300 | Дом явно предлагается в аренду; указана цена $300. |
| 16576 | $350 | `Monthly Rent: $350`; отдельно указан залог за месяц и вода $10/месяц. |
| 16642 | $300 | Вилла предлагается в аренду; исходник на кхмерском указывает цену $300 и срок аренды. |
| 16645 | $450 | В исходнике на кхмерском отдельно указана плата за аренду $450, залог за месяц и коммунальные тарифы. |
| 16662 | $250 | `Monthly Rent: $250`; залог указан отдельно. |

Свежий read-only прогон `scripts/audit-all-pending-v13.cjs` на копии дал 7 карточек без причин: 16565, 16576, 16642, 16645, 16662, 16666 и 16720. В предыдущем сохранённом прогоне без этих трёх новых форм распознавания уже проходили 16565, 16642, 16645 и 16666; дополнительными стали 16576, 16662 и 16720. Счётчик `MONTHLY_PRICE_NOT_CONFIRMED_BY_SOURCE` в этих двух локальных прогонах снизился с 38 до 35.

Точечный тест `npm test -- --runInBand --runTestsByPath tests/source-price.test.ts` прошёл: 1 набор, 23/23 теста. В тестах цена не извлекается из залога, тарифа за электричество/воду, цены продажи или несвязанных чисел; разные варианты аренды сохраняются как конфликт.

## Неоднозначные crossposts: безопасное уточнение причины

В том же read-only снимке проверены все 18 карточек, у которых единственной причиной v13 было `AMBIGUOUS_SOURCE_BINDINGS`. Локальная функция `diagnoseCorroboratedCrossposts()` показывает первое сработавшее защитное условие; обычная функция `evaluateCorroboratedCrossposts()` продолжает возвращать прежнее удержание `AMBIGUOUS_SOURCE_BINDINGS`.

| Первое диагностическое условие | Карточек |
| --- | ---: |
| Разные авторы (`CROSSPOST_AUTHOR_MISMATCH`) | 7 |
| Различаются числовые факты (`CROSSPOST_NUMERIC_FACTS_DIFFER`) | 6 |
| Исходный текст слишком короткий (`CROSSPOST_ORIGINAL_TOO_SHORT`) | 3 |
| Низкое сходство текста (`CROSSPOST_TEXT_SIMILARITY_TOO_LOW`) | 1 |
| Больше 12 источников — текущего предела проверки (`CROSSPOST_COUNT_OUT_OF_RANGE`) | 1 |

Это первая причина остановки для каждой карточки, а не полный список возможных проблем в её источниках. Я подключил диагностику к read-only `scripts/audit-all-pending-v13.cjs`: `diagnosticReasons` показывает причину связи источников, `sourceDiagnostics` — обычные причины v13 для каждого источника отдельно. Обычное решение остаётся `AMBIGUOUS_SOURCE_BINDINGS`. Повторный аудит до/после подтвердил те же 153 Pending, тот же список карточек без причин и неизменные `reasons`/`reasonCounts`. Локальные тесты `canonical-moderation-crossposts` и `canonical-moderation-policy` прошли: 2 набора, 43/43 теста. В production-путь диагностика не подключена.

Отдельные проверки подтвердили, что большинство числовых расхождений нельзя безопасно игнорировать: у ID 263 текст описывает продажу дома с рассрочкой, а не обычную аренду; у 16544, 16585, 16663 и 16673 исходники содержат разные цены или размеры/характеристики объектов; у 16710 среди источников есть несколько противоречий цены. ID 16685 — единственный явный пограничный случай: оба источника по отдельности подтверждают текущие цену и число спален, а один текст добавляет «доступно на 4 этажах». Это может описывать тот же объект с дополнительной деталью либо несколько квартир в доме. Карточка оставлена на ручную проверку; автоматическое ослабление общего числового контроля по ней небезопасно.

## Восстановление фактов из исходников

Отдельный повторный preview вызвал `sourceListingFacts()` для 153 карточек на той же read-only копии. Он предлагает заполнять только отсутствующие поля, которые находятся в первоисточнике. После такой симуляции 11 карточек имели бы ноль причин v13: семь из таблицы выше и ещё четыре:

| ID | Предлагаемые исходником поля | Результат симуляции |
| ---: | --- | --- |
| 16564 | Siem Reap, вилла, 4 спальни, 5 санузлов | Причины исчезают. |
| 16622 | Siem Reap, квартира, 1 спальня, 1 санузел | Причины исчезают. |
| 16665 | Siem Reap, вилла, 2 спальни, 1 санузел | Причины исчезают. |
| 16692 | Siem Reap, дом, 2 спальни | Причины исчезают. |

Эти четыре результата — preview, а не восстановленные production-поля. ID 16627 получает подтверждённый город, но остаётся с `MISSING_LISTING_FACTS`, поэтому в число 11 не входит. ID 16696 после заполнения фактов всё ещё удерживается как `SOURCE_GROUNDED_DUPLICATE`. ID 16670 остаётся на проверке из-за несовпадения структурной цены и противоречивых месячных сумм; ID 16640 также сохраняет несколько независимых причин. ID 16556 не получает город автоматически: у него два текущих источника от разных авторов.

Ранее сохранённая более широкая симуляция `geo_type` давала 12 карточек без причин. Она не принята как итог: в ней ID 16627 проходил без типа объекта, а ID 16696 проходил несмотря на результат проверки исходного дубля. Более консервативный повтор `sourceListingFacts()` выше даёт 11.

## Почему семь карточек остались без AI-фактов

В сохранённых `source_items` у семи карточек отсутствует `listingExtraction`. У шести есть неудачные попытки `SUPPLY_EXTRACTION`, записанные для processing run 173:

- ID 16564, 16622 и 16696 попали в общую группу попыток `3241ab3c-eb4e-49af-974b-71be759f80e7`. Первая модель отклонила весь ответ из-за отсутствующего обязательного `property_type` у одного элемента; следующая вернула неверную форму `items`; ещё две Gemini-попытки получили 503, а Cloudflare завершился таймаутом.
- ID 16627, 16670 и 16692 попали в группу `d520e2cd-cd7b-41c1-a599-1330e4b6f2eb`. Groq вернул 2 элемента вместо 3, Gemini 3.1 вернула некорректный JSON, остальные Gemini-попытки получили 503, Cloudflare завершился таймаутом.
- У ID 16665 есть попытка классификации, но нет записи о попытке извлечения фактов. Почему извлечение не запускалось, по сохранённым данным **не установлено**.

Код `extractSupplyBatch()` валидирует пакет целиком. После исчерпания цепочки попыток он перехватывает ошибку и возвращает пустой набор; обычный путь продолжает обработку классифицированных записей без `listingExtraction`. Повторный replay с `BRIGHTDATA_REPLAY_FILE` останавливается при неполном пакете. Это объясняет, как отдельные сбои нормализации дошли до canonical-карточек с неполными полями и `MISSING_LISTING_FACTS`; это не доказывает, что каждый из этих объектов следовало публиковать без просмотра исходника.

## Вывод и границы

- Подтверждены три новых случая, где месячная цена была в оригинале, но не распознавалась; локальное правило сейчас учитывает их безопасно и пропускает залог/коммунальные суммы.
- Ещё четыре карточки имеют достаточные source-backed факты для прохождения симуляции после восстановления полей. Это отдельная правка фактов и повторная оценка, а не автоматическое разрешение для всех записей без AI extraction.
- Остаточные ошибки извлечения связаны с двумя неудачными пакетами и одним случаем без записанного вызова. Для ID 16670 конфликт цен обоснованно оставляет удержание.
- Результаты 7/11 относятся только к локальному расчёту против снимка от 2026-11-11. Код не развернут, живая база и статусы Pending не изменялись. Для применения любых новых статусов нужен отдельно ограниченный production-план и подтверждение набора ID; прежняя транзакция по 40 карточкам сюда не распространяется.

Артефакты аудита оставлены в `/private/tmp`: `homeasy_pending_v13_recheck_20261112.json`, `homeasy_pending_v13_recheck_diagnostics_20261112.json` и `homeasy_pending_v13_source_facts_preview_result_20261112.json`.
